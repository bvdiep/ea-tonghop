# 📄 Tài liệu Đặc tả Định dạng Dữ liệu Session (OpenClaw)

## 1. Tổng quan cấu trúc lưu trữ
Dữ liệu hội thoại không lưu trong một file duy nhất mà phân tán trong thư mục `sessions/` với 3 loại file chính:
- **`.jsonl`**: File lưu trữ các sự kiện (events) của session theo thời gian thực.
- **`.jsonl.reset.[ID]`**: Các bản sao lưu hoặc trạng thái của session sau khi thực hiện lệnh `/reset` hoặc `/new`.
- **`.trajectory.jsonl`**: File đặc thù lưu trữ "quỹ đạo" suy nghĩ và thực thi của Agent (thường chứa các block context phức tạp).

## 2. Cấu trúc một dòng dữ liệu (JSONL Line)
Mỗi dòng trong file `.jsonl` là một đối tượng JSON độc lập. Có hai dạng chính:

### Dạng A: Sự kiện Tin nhắn (`type: "message"`)
Đây là dạng dữ liệu chính mà chúng mình cần để khôi phục nhật ký.
```json
{
  "type": "message",
  "timestamp": "2026-08-11T01:04:22.123Z",
  "message": {
    "role": "user", // hoặc "assistant"
    "content": [
      {
        "type": "text",
        "text": "Nội dung tin nhắn ở đây..."
      }
    ],
    "timestamp": 1723347862123 // Epoch milliseconds
  }
}
```
**⚠️ Biến thể cần lưu ý:**
- `content` có thể là một **String** đơn giản (thay vì một List).
- `content` có thể chứa nhiều block (ví dụ: `text` kết hợp với `tool_call`).
- `timestamp` có thể xuất hiện ở cả lớp ngoài (ISO 8601) và lớp trong (Epoch ms).

### Dạng B: Context Biên dịch (`type: "context.compiled"`)
Thường xuất hiện trong các file `.trajectory.jsonl`. Đây là dạng dữ liệu "nén" toàn bộ lịch sử cho đến thời điểm đó.
```json
{
  "type": "context.compiled",
  "timestamp": "2026-08-11T01:06:00.000Z",
  "data": {
    "messages": [
      { "role": "user", "content": "...", "timestamp": 123456789 },
      { "role": "assistant", "content": "...", "timestamp": 123456790 }
    ]
  }
}
```
**⚠️ Biến thể cần lưu ý:** Một dòng `context.compiled` có thể chứa hàng chục tin nhắn. Nếu chỉ đọc từng dòng đơn lẻ, chúng mình sẽ bỏ lỡ toàn bộ khối dữ liệu này.
